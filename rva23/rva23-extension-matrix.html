Why RVA23 matters — the ISA milestones at a glance

RVA23 is the release where the RISC-V Application Profile reaches Armv8.0–v8.4 baseline parity for phones and servers. Inside the ISA profile itself, the headline upgrades are:

  • Vector (V) becomes mandatory in U64 — every conformant chip ships RVV 1.0. SIMD is no longer optional. New in RVA23.
  • Hypervisor (H) becomes mandatory in S64 via the Sha umbrella — KVM-RISCV, pKVM, Android protected VMs. Was optional in RVA22S64. The biggest single change for system silicon.
  • Vector-crypto base mandatory: Zvbb + Zvkt (vector bit-manipulation + data-independent timing). AES-GCM via optional Zvkng / SM4-GCM via Zvksg. Closes the ~13-year gap to Arm's AESE/AESD/PMULL.
  • Pointer masking (Supm) mandatory in U64 — tagged-pointer ABI for HWASan, GC-style runtimes, plus parity with Arm TBI / MTE's userspace control surface.
  • Scalar quality-of-life: Zicond (conditional move), Zfa (FP additions / immediate loads), Zicboz + Zicbom (cache-block ops), Zawrs (low-power spin) — closes long-standing scalar performance gaps with Arm and x86.
Several adjacent features that vendors typically bundle with "RVA23-class" products are not in the ISA profile and so do not appear in this matrix — in particular AIA (Ssaia/Smaia for scalable interrupts and PCIe MSI), IOMMU, RAS, ACPI / DT bindings, SBI v2.0+. ISA extensions added on top of RVA23S64 — Server Platform Hardware Rules § RISC-V Harts

RVA_020 MUST7 mandatory ISA additions
  • Sv48
    48-bit virtual addressing. RVA23S64: optional → promoted to MUST.
  • Sdtrig
    Debug triggers. SEE_020 further mandates ≥4 instruction-address and ≥4 load/store-address match triggers. RVA23S64: optional → promoted to MUST.
  • Sdext
    External debug extension. NEW — not in RVA23S64.
  • Zkr
    Entropy-source CSR (seed) — servers need entropy at boot. RVA23S64: optional → promoted to MUST.
  • Ssccfg
    Counter configuration extension. NEW — not in RVA23S64.
  • Ssstrict
    Implementation must not include non-standard extensions or use reserved encodings. RVA23S64: optional → promoted to MUST.
  • Ssaia
    S-mode part of the Advanced Interrupt Architecture — the ISA-level CSRs paired with platform-level APLIC/IMSIC. This is the "AIA piece" that RVA23 itself does not require. NEW — not in RVA23S64. Spec note: "These mandates may be moved into a new ISA profile specification."
RVA_030 / 040 SHOULD2 recommended ISA additions
  • Svadu
    Hardware A/D-bit updating in page-table entries. RVA23S64: optional → still optional. "Expected to become mandatory in a future version."
  • Ssctr
    Control Transfer Records. If implemented, a CTR depth of 32 is mandatory (uniform depth aids VM migration; useful for profile-guided optimisation). NEW — not in RVA23S64. "Expected to become mandatory in a future version."
RVA_060 MUSTSizing constraint on an already-mandatory extension
  • Zihpm ≥ 6
    At least 6 hardware performance counters, on top of the three defined by Zicntr. Not a new extension — a minimum-instance count on one RVA23 already mandates.

Firmware / SBI — Server Platform Firmware Rules

  • FIRM_010 MUSTBRS-I recipe from Boot & Runtime Services v1.0
  • FIRM_020 MUSTSBI v3.0 DBTR (Debug Triggers) — required so S-mode can drive Sdtrig
  • FIRM_030 if-RASSBI v3.0 SSE (Supervisor Software Events) — required when any RISC-V RAS support is present
  • FIRM_140 MUSTIOMMU described via RIMT ACPI table
  • FIRM_150..170Forward-edge CFI in UEFI runtime services (signaled via EFI memory-attribute flag; entry must be lpad 0)

Platform hardware — SoC, peripherals, interrupt controller, IOMMU

  • HSOC_010 MUSTSoC complies with Server SoC v1.0 (a separate spec)
  • HSOC_020 MUSTVM-assignable / userspace-driver peripherals must be PCIe (or SoC-integrated PCIe). APLIC, IOMMU, debug, RoT explicitly excluded.
  • implicitInterrupt controller (typically APLIC per the AIA spec) — required via Ssaia + HSOC rules
  • implicitIOMMU per the RISC-V IOMMU spec — required for PCIe device assignment to VMs
  • HPER_010 MUST16550- or PL011-compatible UART (115200 baud, flow control, IRQ-driven)
  • HPER_030..040If USB present: XHCI 1.2+; if SATA present: AHCI 1.3.1+ (both with 64-bit addressing)
  • HPER_070 MUSTBattery-backed RTC for UEFI certificate validity
  • HPER_090 MUSTTPM 2.0 (TPM 2.0 Library spec)

Security — Server Platform Security Rules

  • SEC_010 MUSTHardware Root of Trust, isolated from the application processor (examples: OpenTitan, Caliptra)
  • SEC_020 MUSTRoT manages a security lifecycle: Manufacture → Provisioning → Secured → Recoverable Debug → Terminated
  • SEC_030 SHOULDRoT-rooted secure identity + platform attestation (TCG DICE / SPDM)
  • SEC_040 MUSTUEFI Secure Boot + driver signing
  • SEC_080..100 MUSTIn-band firmware updates with signed payloads + signature validation before applying

Platform-layer items not covered: RVA23 is a CPU-ISA-only profile. The following components are required by RISC-V platform specs (Server Platform, BRS / EBBR / SBBR) but are not part of any RVA profile and so do not appear in this matrix. For a structured view of what the server platform spec adds on top of RVA23, see the Server Platform v1.0 tab above.
  • IOMMU — DMA address translation. Spec: RISC-V IOMMU Architecture Specification (ratified 2024). Reuses CPU PTE formats (Sv39x4 / Sv48x4 / Sv57x4) and inter-operates with H-extension G-stage translation. Linux: drivers/iommu/riscv/ (v6.13+).
  • AIA / IMSIC / APLIC — Advanced Interrupt Architecture. Specs: Ssaia / Smaia extensions, optional and not listed in RVA23. Linux: drivers/irqchip/irq-riscv-{imsic,aplic}-*.c.
  • RAS — Reliability / Availability / Serviceability. Spec: RERI (RISC-V Error Reporting Interface).
  • ACPI / Device Tree bindings — Extension discovery via ACPI RHCT or DT riscv,isa-extensions; SBI capability probing.
  • Firmware interfaces — SBI (Supervisor Binary Interface) versions, UEFI requirements (SBBR-RV / EBBR-RV), secure-boot chain.
