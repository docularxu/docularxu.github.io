Why RVA23 matters — the ISA milestones at a glance

RVA23 is the release where the RISC-V Application Profile reaches Armv8.0–v8.4 baseline parity for phones and servers. Inside the ISA profile itself, the headline upgrades are:

  • Vector (V) becomes mandatory in U64 — every conformant chip ships RVV 1.0. SIMD is no longer optional. New in RVA23.
  • Hypervisor (H) becomes mandatory in S64 via the Sha umbrella — KVM-RISCV, pKVM, Android protected VMs. Was optional in RVA22S64. The biggest single change for system silicon.
  • Vector-crypto base mandatory: Zvbb + Zvkt (vector bit-manipulation + data-independent timing). AES-GCM via optional Zvkng / SM4-GCM via Zvksg. Closes the ~13-year gap to Arm's AESE/AESD/PMULL.
  • Pointer masking (Supm) mandatory in U64 — tagged-pointer ABI for HWASan, GC-style runtimes, plus parity with Arm TBI / MTE's userspace control surface.
  • Scalar quality-of-life: Zicond (conditional move), Zfa (FP additions / immediate loads), Zicboz + Zicbom (cache-block ops), Zawrs (low-power spin) — closes long-standing scalar performance gaps with Arm and x86.
Several adjacent features that vendors typically bundle with "RVA23-class" products are not in the ISA profile and so do not appear in this matrix — in particular AIA (Ssaia/Smaia for scalable interrupts and PCIe MSI), IOMMU, RAS, ACPI / DT bindings, SBI v2.0+. Platform-layer items not covered: RVA23 is a CPU-ISA-only profile. The following components are required by RISC-V platform specs (Server Platform, BRS / EBBR / SBBR) but are not part of any RVA profile and so do not appear in this matrix:
  • IOMMU — DMA address translation. Spec: RISC-V IOMMU Architecture Specification (ratified 2024). Reuses CPU PTE formats (Sv39x4 / Sv48x4 / Sv57x4) and inter-operates with H-extension G-stage translation. Linux: drivers/iommu/riscv/ (v6.13+).
  • AIA / IMSIC / APLIC — Advanced Interrupt Architecture. Specs: Ssaia / Smaia extensions, optional and not listed in RVA23. Linux: drivers/irqchip/irq-riscv-{imsic,aplic}-*.c.
  • RAS — Reliability / Availability / Serviceability. Spec: RERI (RISC-V Error Reporting Interface).
  • ACPI / Device Tree bindings — Extension discovery via ACPI RHCT or DT riscv,isa-extensions; SBI capability probing.
  • Firmware interfaces — SBI (Supervisor Binary Interface) versions, UEFI requirements (SBBR-RV / EBBR-RV), secure-boot chain.
